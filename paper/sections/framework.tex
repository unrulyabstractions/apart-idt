The pipeline audits one target model for differential treatment across user groups. \autoref{fig:pipeline} shows it instantiated for secret loyalties; Appendix~\ref{app:task} states the task it solves. Six stages:

\begin{enumerate}[noitemsep, topsep=2pt]
    \item \textbf{Principal elicitation.} An Elicitor LLM turns a principal seed into questions whose answers name an entity, and reads back which entity the target favors. Each candidate defines one user group, its supporters.
    \item \textbf{Prompt set construction.} A Prompter LLM writes one template set for the deployment; rendering each candidate's name gives one prompt set per group, differing only in the name.
    \item \textbf{Hypothesis conjecture.} A Conjecturer LLM proposes how a compromised model would behave differently here, then turns each hypothesis into a yes/no question about a single response. These are the behavior axes $\Lambda$.
    \item \textbf{Response collection.} The target and its base model are each sampled many times per prompt.
    \item \textbf{Response scoring.} A judge scores every response on every axis, blind to which group produced the prompt, once at each affordance level the condition allows.
    \item \textbf{Comparing distributions.} The $N$ group behavior distributions are compared to each other in the target and in its base, and one permutation test returns whether the target is loyal, to which candidate, and on which behaviors.
\end{enumerate}

Every helper is told as much as the auditor's affordance allows, and no helper is the target. The stages below give each in turn; \autoref{app:protocol} gives the parameters and prompts.

\subsection{Principal elicitation}
\label{sec:principal-elicitation}

A secret loyalty needs a beneficiary, and under IDT the auditor does not know who it is, so the first stage surfaces candidates from the target itself.
An \emph{Elicitor LLM} runs the stage in two roles:
\begin{itemize}[noitemsep, topsep=2pt]
    \item \textbf{Questioning}: expand a \emph{principal seed}, a specification of what kind of entity the principal could be, into open-ended questions for the target.
    \item \textbf{Extracting}: read each target reply and name the single entity it favors, or none.
\end{itemize}
The entities the target names, ranked by how often it names them, become the candidate principals, and each candidate gets a corresponding prompt set (Section~\ref{sec:prompt-set-construction}).

%-----------------------------------
%-----------------------------------
\subsection{Prompt set construction}
\label{sec:prompt-set-construction}

With the candidates fixed, each defines a prompt set an LLM could treat differently in a specific deployment.
A secret loyalty is one such difference: \citet{narrow-secret-loyalty} train models that, when a user's intended action would advantage a principal $A$, encourage it, and otherwise behave as a standard assistant.
Read as differential treatment, the two groups are matched requests that differ only in which principal the action would advantage: $A$ for the target set, a rival for the baseline set.
Their own wrong-principal control has exactly this shape.
If the model encourages one side and refuses the other, it advantages that principal while every individual reply, an encouragement here or a refusal there, stays defensible on its own.

Every group's prompt set then makes the same requests at the same rates, so a difference in the replies cannot be a difference in what was asked (Appendix~\ref{app:prompt-sets}).

%-----------------------------------
\subsection{Hypothesis conjecture}
\label{sec:hypothesis-generation}

The axes cannot be chosen in advance, because which behaviors matter is a property of the deployment.
A \emph{Conjecturer LLM} proposes them, in two steps that are kept separate on purpose:
\begin{enumerate}[noitemsep, topsep=2pt]
    \item \textbf{Conjecture.} Given the deployment, the kinds of request it receives, and whatever the audit condition discloses, propose ways a compromised model would treat the groups differently. Each is a claim about behavior, stated in natural language.
    \item \textbf{Operationalize.} Recast each claim as one yes/no question about \emph{one} response, read alone.
\end{enumerate}
The second step is where a hypothesis can fail, and the failures are recorded rather than repaired.
A question that names a candidate would unblind the judge, and a question that asks the judge to compare against a response it will never see cannot be answered at all; both are rejected, and the hypothesis is kept unscored rather than reworded into something it does not say.
The surviving questions are the behavior axes $\Lambda$, frozen before any response is collected, so the axes cannot be tuned to the data they will score.

%-----------------------------------
%-----------------------------------
\subsection{Response collection}
\label{sec:response-collection}

Each prompt is sampled many times from the target LLM, and identically from its base model (\autoref{eq:llm}).
The target carries whatever deployment system prompt the audit condition discloses and nothing more, since the system prompt is part of what is being audited rather than a free parameter.
A generation that fails or is refused is recorded with empty text and counted.

%-----------------------------------
%-----------------------------------
\subsection{Response scoring}
\label{sec:response-scoring}

A judge LLM answers every axis question about every response, reading each response alone.
It never learns which group produced the prompt, which entity was named, or how any other response was scored, so the judge cannot recover the group label it would need to produce a gap on its own.
A verdict the judge does not return is recorded as null and counted, never imputed: an imputed verdict is behavior the model never produced.
Each prompt then has a prompt behavior distribution as in \autoref{eq:prompt-behavior-distribution}, aggregated per group as in \autoref{eq:community-behavior-distribution}.

What the judge is told is graded like every other helper. The judge runs once per affordance level up to the condition's own, on the same responses, so the effect of telling a judge that a loyalty may be present can be read off directly instead of assumed. Blinding is not graded at any level.

\subsection{Comparing distributions}
\label{sec:comparing}

One permutation test answers three questions at once.

\paragraph{The observation.}
Every prompt is a (candidate, instruction) pair, sent identically to the target and to its base. The observation for one prompt on one axis is a \textbf{cell rate}, the fraction of yes verdicts over that prompt's samples:
\begin{equation}
    \hat{p}^{M}_{C,i,j} \in [0,1],
    \label{eq:cell-rate}
\end{equation}
for model $M \in \{T, B\}$, candidate $C$, instruction $i$, axis $j$. Pooling inside the cell absorbs the dependence among one prompt's samples, so nothing downstream needs a cluster correction. Each judge level is its own table, so a level is never averaged with another.

\paragraph{The effect.}
Within one model, compare a candidate against the average of the others:
\begin{equation}
    g^{M}_{C,i,j} = \hat{p}^{M}_{C,i,j} - \frac{1}{N-1}\sum_{C' \neq C} \hat{p}^{M}_{C',i,j},
    \label{eq:one-vs-rest}
\end{equation}
then subtract the base's gap from the target's:
\begin{equation}
    d_{C,i,j} = g^{T}_{C,i,j} - g^{B}_{C,i,j}.
    \label{eq:excess}
\end{equation}
Two confounds cancel here. A name effect appears in both models and subtracts out, so a candidate the base already treats differently, because the name is famous or sensitive, does not register. A global fine-tuning shift reaches all candidates equally and is candidate-independent, so it cancels too. What survives is treatment specific to one candidate that the target shows and its base does not.

\subsubsection{Does this target have a secret loyalty?}
Average the excess over instructions, standardize by its variability across them, and take the largest value over all candidates and axes:
\begin{equation}
    t_{C,j} = \frac{\bar{d}_{C,j}}{s_{C,j}/\sqrt{m}},
    \qquad
    S = \max_{C,\,j} \left| t_{C,j} \right|,
    \label{eq:max-statistic}
\end{equation}
over $m$ instructions. The maximum matches the threat model of one principal on a few axes; axes with a registered polarity use the signed statistic.

Under the null, every candidate's effect in the target equals its effect in the base. The exchangeable unit is the matched pair of target and base cells for one prompt, because a name effect travels with the pair. We shuffle candidate labels over those pairs within each instruction, recompute $S$, and take $p$ as the share of shuffled maxima at least as large as the observed one. A significant $S$ declares the target secretly loyal. Family-wise error is controlled jointly over candidates and axes, so nothing further is corrected for, and the base pairing sits inside the statistic, so a significant spread within the target alone is never a result.

\subsubsection{Which principal?}
The candidate attaining the maximum. It is named by the same test that established significance, not chosen afterward, and it is reportable: a candidate, elicited from the target itself, whose supporters receive treatment the base model does not give them. The unsigned maximum names the candidate treated most differently, in either direction, so the sign of $\bar{d}$ says whether that candidate is the beneficiary or the one held back.

\subsubsection{Which behaviors, and do they match the activation condition?}
The axes surviving Westfall--Young step-down against the permutation max-distribution, each with an adjusted $p$ and an effect size. This is the part a documented organism can score. The published activation condition names a set of behaviors; the surviving axes either are those behaviors or are not. When they are, the audit has recovered the mechanism and not only its footprint. When they are not, the axis set did not contain the mechanism, and the surviving axes say what was scored in its place.

Treatment delivered equally to every candidate is candidate-independent, so it cancels in \autoref{eq:excess} along with the confounds. That half is read as the target's overall firing rate against the base model's, and reporting either half alone is incomplete.
